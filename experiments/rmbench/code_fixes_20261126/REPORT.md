# 2026-11-26 修正与执行安排

## 已应用的修正

- RGB 路径增加显式 rgb_normalization 配置。新版使用 identity，让 0～1 图像直接进入 ImageNet 标准化。历史协议缺少该字段时仍按原来的 range 路径读取，权重保存的归一化器随 checkpoint 加载。
- 训练、阈值校准、接口检查和未训练策略验证都读取同一个视觉配置。新训练模板采用 identity，并重新计算记忆写入阈值。
- 训练已完成但尚未评测的权重缺失时，调度器报告 missing_artifact 并停止误报完成。
- 早期数据准备默认选择一张空闲卡，训练和评测入口统一限制到最多两张卡。
- 旧 Coffee 评测使用独立的固定随机数范围，并恢复训练中的 Python、NumPy、Torch 随机数。
- 补充五项任务的只读初态与阶段记录，包括观察后抓取的目标、首次双指接触、目标高度和提前移动标记。
- 单卡调度支持在训练和评测之间填充空闲槽，保持最多四项独立任务。

## 对历史结果的影响

RGB 范围问题确实存在于旧 M0 与 M5 的视觉输入中，影响训练和推理。旧成功率仍是旧实现条件下实际完成任务的次数。修正后的分数由新一轮训练与闭环评测给出。

审查时已完成训练的相关任务均保留五个权重，缺失权重的调度故障未在这些任务触发。资源上限、轨迹记录和旧 Coffee RNG 的修正分别影响后续资源安排、失败分析和早期 Coffee 恢复路径。

按用户最新指令，沿用官方任务的专家采集流程、挡板触发、动作执行、成功判定和步数上限。此次修改位于本项目的适配、调度、随机数与记录代码。此前改变挡板采集时序的安排撤回。

## 当前训练批次

旧版三项完整结果保留，方块归位为 100%，方块覆盖为 80%，观察后抓取为 6%。

剩余六项在 experiments/rmbench/m5_seed0_rgb_corrected 的独立目录从头训练完整 M5 种子 0，使用新版 RGB 预处理。任务为方块交换、电池试插、方块重排、T 形块交换、方块排序试验和按按钮。原始实验的断点和评测结果仍在原目录。

原来的有效初态清单已复用。排序与按按钮原先只保存了专家筛选前缀，正式评分前由原有专家有效性筛选流程补齐 50 个初态。每项仍训练 250 轮，在 50、100、150、200、250 轮各跑 50 回合。汇总表逐项注明预处理版本。

本批使用 H200 GPU 5 的四个并行槽。已有评测权重时并行评测，无现成评测时填充训练任务。
