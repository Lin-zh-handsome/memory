# 记忆写入阈值：文献对照与当前方案评估

日期：2026-11-26。

结论：逐任务使用训练数据自动确定阈值，可以作为统计适配方案。当前依据不足的地方是用初始化M3特征计算固定阈值，再供持续训练的M5使用；以及校准样本对与实际写入比较对象不同。这些是需要验证的机制风险，不等于已经证明当前策略无效。

## 当前实现事实

1. 每任务从50条训练示范中取编号0、7、14、21、28、35、42、49，用相邻帧两类余弦相似度的20%分位数确定视觉和历史阈值。
2. calibrate.py显式构建M3；ResNet18无预训练权重。校准发生在优化器更新前，数值随后固定。
3. M3包含过去动作预测头，M5没有；该头在事件视觉投影前初始化。当前流程未保证M3和M5写入评分参数一致，不能仅凭相同随机种子认定视觉评分分布一致。
4. 实际OrderedEvents.write与最近入库事件比较，而校准比较相邻帧。任一分支低于阈值即写入，且保留首帧、8槽容量及既有淘汰机制。

## 技术判断与待验证项

- 逐任务训练数据统计适配本身可接受，应统一数据使用范围与分位数规则，避免根据正式评测成绩逐任务挑选阈值。
- 未训练特征到已训练特征的分布漂移、M3到M5的评分一致性需要直接核对。尚不能据此宣称已导致低成功率。
- 两个边缘20%分位数不意味着最终20%写入率。即使同分布、连续分数下各分支触发率均为20%，两者取或时联合率可为20%–40%；实际比较最近入库事件后，不能再直接套用这个范围。
- 八条示范和20%分位数属于启发式设定，现有检索证据没有直接验证这一具体组合。
- 前述“不同随机种子必须共用同一组数值”过于绝对。应首先固定校准规则；共享实际数值需评分器共享或尺度稳定作为依据。

## 最小后续验证建议（尚未执行）

1. 使用相同训练示范，比较校准时M3、初始化M5与已训练M5的评分分布。统计总写入率、分支触发率、可替换槽保留的时间跨度与关键阶段覆盖。
2. 在1–2项历史依赖任务做有限阈值敏感性诊断（如分位数0.1/0.2/0.3），保留官方规则和配对初态。同权重改变门控仅用于敏感性诊断；如确定更改训练方案，应再做同预算训练比较。
3. 若阈值稳定且闭环不敏感，保留当前简洁机制；若接近全写/全不写，比较全写入对照并优先处理评分一致性，再决定是否修改门控。
