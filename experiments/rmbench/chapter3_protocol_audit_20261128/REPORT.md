# 第三章模型、训练和RMBench评测审查

审查日期：2026年11月28日。对象为服务器当前实际运行的第三章实现及现有结果。只读模型/实验代码，审查产物写入服务器；未修改模型、训练和评测代码、官方任务规则，未停止当前单卡实验，未启动新的GPU作业。

**结论：本轮未发现把失败记作成功、额外泄漏任务答案、放宽动作上限或改写官方控制规则造成的虚高。已完成高分有逐回合记录和几何证据支持。但使用的是项目自己的策略适配器与统计设置，不能称为官方DP默认配置和论文100回合口径的逐项复现。**

按用户最新安排，RGB新旧版本比较只留待办，本轮不处理、不重配对照、不重跑，不将其作为本轮后续工作的中心。

## 一、范围与方法

- 对当前RMBench目录29个Python文件（6567行）作关键环境状态写入静态扫描，未发现对eval_success/check_success/step_lim/阶段真值的赋值；模型、训练、数据、目标构造、归一化、校准、种子、回放、分片及汇总主链路逐段审阅。其余历史入口/资源脚本按调用及参数路径核查。
- 读取Stanford Diffusion Policy的策略类、视觉编码器、裁剪、采样、归一化及EMA关键实现。
- 在线读取RMBench官方GitHub README、固定版本评测和任务源码，同时逐项对照服务器三处环境补丁及实际coffee-dp环境的Mplib TOPP实现。
- 数值检查九任务450条专家示范的数组长度、维度、动作/下一状态对齐和训练/评测种子隔离；只用CPU读取数组/元数据。
- 审核45个完整评测节点的2250条逐回合记录，另做Mamba极小递推/因果/掩码核查及高分几何复算。2250是不同模型和检查点的日志条数，不是2250个独立训练或独立初态。
- 本轮没有重新运行完整GPU模型或仿真回放。代码与已有记录支持的结论、缺少原始日志的部分及需新实验的问题分别列明。

主要工作记录：[模型](model_audit.md)、[训练和数据](training_audit.md)、[官方评测与环境](official_eval_audit.md)、[逐回合证据](artifact_audit.json)、[几何复算](geometric_audit.json)。

## 二、模型和训练链路

| 审查项 | 结论与依据 |
|---|---|
| 原扩散基线 | models.py:54–55直接使用原DiffusionUnetImagePolicy类。ResNet18、条件1D U-Net及DDPM预测噪声/反向采样采用原实现；输入视角、分辨率、时域及采样组织由本项目配置，不是当前RMBench官方DP默认配置。 |
| 连续Mamba | models.py:66–117同时传递卷积与SSM双缓存；新示范和新回合清空，段间只切断梯度。极小CPU核查整段/分段/逐帧一致，未来token对此前输出梯度为0；不是整回合完整反向传播。 |
| 八槽检索 | 每环境单独保存状态，读后再写、有效槽掩码和空库处理正常；没有跨回合/环境串用，也没有以真实任务阶段触发写入。 |
| 辅助监督 | 冻结R3M关键帧特征仅作为训练标签进入预测头损失；在线输入仅RGB+14维关节，predict_stream不调用教师或预测头，不把未来关键帧标签直接作为动作条件。 |
| 时间对齐 | 九任务450条示范检查通过，action[:-1]与state[1:]最大差为0；与官方HDF转换时state[:-1]/action[1:]/RGB[:-1]一致。短窗动作起点与n_obs_steps=2配套。 |
| 训练预算 | 同任务四模型共用同一批锚点及更新数；时间段按示范顺序连续读取，示范顺序按训练种子/轮次打乱。M5与memory_only共用同一增强路径。 |
| EMA与推理 | 每优化步更新EMA，评测加载EMA并eval；归一化统计来自训练集并随检查点加载，不用测试数据重新拟合。GroupNorm和因果状态处理未发现未来帧通过批统计泄漏。 |
| 断点 | 保存/恢复模型、EMA、优化器、学习率调度、随机状态、样本位置和完整循环状态；未发现漏恢复状态。 |
| 种子隔离 | 官方演示训练种子与已生成评测初态清单交集为空。尚未完成评测的清单不当作已完成50初态使用。 |

模型和训练未发现新的P0级正确性错误。以下是机制解释限制，而非“成功率假的”：
1. mamba_only到memory_only不仅加八槽/Cross-Attention（交叉注意力），也加共享融合MLP（多层感知机）；当前四组消融可比较整个记忆分支，不能把全部增益单独归给检索。
2. 64步截断反向传播保留跨段历史数值，但不把梯度传回64步之前；固定阈值及槽是否保留中期事件需要机制实验，不由成功率自动证明。
3. 八槽是八个历史事件槽，不是保证八个语义子任务完成帧；现有少量日志可见早期槽保留与中期替换。

## 三、是否按官方评测流程

| 环节 | 官方代码 | 当前实现 | 判断 |
|---|---|---|---|
| 初态资格 | play_once后plan_success and check_success，再按同一seed重新初始化 | evaluate.py:138–179先独立生成共同合格清单，回放重置对应seed | 核心规则一致；不是按M5能否成功挑初态 |
| 策略输入 | 通过模型适配器选择观测 | evaluate.py:218–236仅RGB与关节；日志真值独立存储 | 未发现目标编号、真实子任务或正确组合进模型 |
| 动作窗口 | 原生入口/XPolicyLab逐个关节目标调用take_action，窗口内更新观测 | evaluate.py:338–357同样调用qpos，动作后更新连续历史 | 未发现跳过控制或偷加专家动作 |
| 控制执行 | 原Mplib TOPP、每1/250秒物理子步与成功检查 | 三处补丁不改此循环，只减少CuRobo初始化/指定渲染设备 | 未发现由补丁放宽约束 |
| 成功判定 | 任务完整check_success，由环境置eval_success | evaluate.py:379只存env.eval_success，阶段只做日志 | 未把中间阶段当终局成功 |
| 时长上限 | 官方_eval_step_limit.yml与take_action_cnt | evaluate.py:88–101强制核对同一上限 | 未放宽 |
| 诊断 | 成功函数有状态副作用 | 诊断只读取位姿/关节/阶段；未额外调check_success | 未发现诊断推进阶段或抬分 |
| 失败与续跑 | 成功按整回合统计 | 固定种子顺序保存成批完整回合；异常不会替换成更易种子；分片保持0–26/26–50边界 | 当前完整记录未发现漏失败、重复计入或不一致 |

三处补丁详见官方评测分报告。qpos复位虽复用Mplib对象，但实际TOPP只用传入关节路径和固定速度/加速度限制，不查询旧场景，未发现控制变容易的机制。

## 四、已完成成绩的逐回合审计

45个完整节点、2250条记录中：
- summary成功数和逐回合布尔success一致；
- 每完整节点均为50条、episode_id为0–49、种子顺序与对应清单一致；
- 无同节点重复种子、无分片和主记录成功标志冲突；
- 观察数=动作数+1，无回合超官方目标调用上限；
- 1900对可比较的重复初态记录在共同字段上按1e-5数值容差一致；
- 当前M5的31个完整节点共有952条成功记录；其中948条有相应末态诊断字段，未见与能复核的官方条件矛盾。旧观察后抓取4条成功日志缺少目标高度/失败标志，只能核查原成功代码及计分一致，不能把缺字段当作失败。

## 五、与官方论文/默认DP配置不同的地方

这些是已确认协议差异，不是自动判定算法无效：
- 论文§5.1为每任务50条专家示范、100回合；项目每个检查点50回合。
- 项目在同一50初态上评50/100/150/200/250轮，再取最好。这既用于选点又用于报告，会产生选择偏差；官方论文没有在所查段落规定同样的“五个检查点最大值”口径。
- 当前官方XPolicyLab DP默认三相机、320×240、时域/观测/执行为8/3/6；本项目单头相机96×96、16/2/8。M0是原DP算法类的自定义配置，不能写成RMBench作者DP基线的逐项复现。
- 当前批量2环境的采样随机流固定为首seed+1000003×动作块号。固定批次下可续跑复现，但与官方模型服务的随机流不是同一实现；不能假定换批大小仍得到逐回合相同动作。

要正式比较外部论文，优先冻结权重后使用独立的新100个官方合格初态，并把当前50回合留作开发集。现有五节点成绩保留，暂不改协议或追加作业。

## 六、发现的官方按按钮代码缺陷

官方固定版本envs/press_button.py:199在复位check_button（确认键）时，取的是button1（第一个计数键）的关节位置，而不是确认键自己的位置。代码对象读取错误已确认，且在官方GitHub相同版本核对。按钮1受压可能影响确认键复位及后续确认标志；是否在某回合触发误判，尚需按钮关节/接触轨迹或针对性仿真。

这段代码没有被项目修改。它不解释方块重排、T型块等高分；当前按按钮没有完整成功成绩。遵照用户“官方规则不改”的要求，本轮不修环境、不改成功数。

观察后抓取第20次成功检查加挡板也是官方原样逻辑，计的是物理子步，而不是20次策略观测；本轮未改。
